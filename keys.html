    AR try-on · Snap Camera Kit — Change
    A long code starting with eyJ.
    Looks like xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.

    The name you published the shirt Lens under.
    Wins over the name if both are set.
    How do I get these?
    1. Sign in at my-lenses.snapchat.com with the shop's Snapchat account. Create an Organization for the shop if it doesn't have one.
    2. Turn on Camera Kit for that Organization at my-lenses.snapchat.com/camera-kit and create an app there. If it asks for the Android package name, enter com.ksprintexpress.fitfusion.
    3. Copy the app's API token from the Snap developer portal at kit.snapchat.com/manage and paste it into API token. Use the Production token for customers. The Staging token puts a “Camera Kit Staging” watermark on the camera, which is fine for testing.
    4. Publish the shirt Lens to the shop's Organization: open the lens-studio/FitFusionShirts project from the app's source folder in Lens Studio, press Publish Lens, pick the Organization, create a Lens Folder, and submit. “Save As Draft” or Offline is quickest because it only goes through automatic checks. Type the name you gave it into Lens name.
    5. Open Lens Scheduler in My Lenses. Add your Lens Folder as a Lens Source. Then go to the Lens Group tab, choose Add New Lens Group, then Add Lens, pick the shirt Lens and press Save Changes.
    6. Click the group and copy its Lens Group ID into this form. The Lens ID is optional; it's listed on the All Lenses tab.
    7. Press Save, then open AR try-on in the app to check.

    The token and the Lens Group must come from the same Camera Kit app, so this form saves them together.

    Photo & design uploads · Cloudinary — Change
    Letters, numbers and dashes.
    The preset's name, not an API key.
    How do I get these?
    1. Sign in or sign up at console.cloudinary.com with the shop's account. The free plan is enough to start.
    2. Copy the Cloud name shown on the Console's dashboard.
    3. Open Settings (the gear) → Upload → Upload presets → Add upload preset. Set Signing mode to Unsigned, save, and copy the preset's name.
    4. Fill in both boxes and press Test upload. It sends a 1-pixel image to the kustomoimprenta/test folder, which you can delete later.
    5. Press Save. The app and this admin site's Design Studio upload to the new account from then on. Images uploaded before stay on the old account.

    Only an unsigned upload preset goes here. Never paste Cloudinary's API secret: anyone signed in to the app can read this page's keys.

    Google key · address search —
    Starts with AIza. Used for the address suggestions in checkout and the profile.
    How do I get this?
    1. Open console.cloud.google.com and pick or create the shop's project. Google requires a billing account on it; the monthly free allowance covers a small shop.
    2. APIs & Services → Library: turn on Places API (New) and Maps SDK for Android.
    3. Credentials → Create credentials → API key.
    4. Restrict it: Android apps → package com.ksprintexpress.fitfusion with the SHA-1 of the app's signing key, and allow only the two APIs above.
    5. Paste it here and save. Then search an address in the app; this page's checklist shows whether Google accepted it.

    The map picture in checkout still uses the key built into the app (see Google map picture below). An Android-restricted key is safe to keep here: it only works from this app.

    Presets —

    Needs a new app build

    Built into the app file. Change them in the project, then build the app again.

    PayMongo · GCash payments Money goes to this account Customer payments go to whichever PayMongo account this key belongs to. The key is now saved on the Payments page.
    1. Sign in at dashboard.paymongo.com with the shop's account. To take real payments, the shop must first complete PayMongo's business verification.
    2. Go to Developers → API Keys and copy the Secret key. Use the test key (sk_test_…) until a full order works, then the live key (sk_live_…).
    3. Paste it on the Payments page and press Save key. No new app build is needed.
    4. Place a test order with GCash.

    How it's kept safe: the Payments page saves the key where nobody can read it back, not even this site or the app. Only the shop's payment server reads it. Until that server is set up (Payments → Setup), the app uses paymongo.secret.key from local.properties if the build has one.

    Firebase · accounts, database and Google sign-in The app and this admin site both run on Firebase, so it's handed over rather than typed in here.

    Easiest: hand over this project

    1. Open the Firebase console for this project → ⚙ Project settings → Users and permissions.
    2. Add member: the shop's Google account, role Owner.
    3. Once the shop has signed in, remove the developer's account.

    No new app build. Products, orders, customers and admins all stay. The Google Maps key can live in the same project.

    Or: the shop's own new project (starts empty)

    1. Create a project at console.firebase.google.com.
    2. Add an Android app: package com.ksprintexpress.fitfusion plus the SHA-1 of the signing key. Download google-services.json and replace app/google-services.json in the project.
    3. Authentication → Sign-in method: turn on Email/Password and Google.
    4. Firestore Database → Create database. On its Rules tab, paste the rules copied from the old project, plus the rule under One-time Firestore setup.
    5. Add a Web app in Project settings and copy its firebaseConfig values into js/firebase.js of this admin site.
    6. Register in the app, then in Firestore open users → that account and set role to super_admin. Sign in here and add the products again.
    7. Build the new app.
    Signing key · who the app belongs to Android installs updates only when they're signed with the same key, and Google sign-in and the Maps key check it too.
    1. In Android Studio, choose Build → Generate Signed App Bundle or APK → Create new…. Keep the .jks file and both passwords somewhere safe. If they're lost, the app can never be updated on Google Play.
    2. Find the key's SHA-1. In Android Studio's Terminal, run keytool -list -v -keystore "path\to\your-key.jks" and copy the SHA1: line.
    3. Add that SHA-1 in Firebase (Project settings → your Android app → Add fingerprint), then download google-services.json again. Also add it to the Google Maps key's Android restriction.

    Until then, the release app is signed with the developer's test key. It installs fine for testing, but it isn't the shop's.

    Build the new app
    1. Open the app's project folder in Android Studio.
    2. Open local.properties in the project's top folder and fill in the lines shown here. Keep the sdk.dir line Android Studio put there.
    3. File → Sync Project with Gradle Files.
    4. Build → Generate Signed App Bundle or APK → APK. Choose the shop's signing key and release, then Create.
    5. Share app-arm64-v8a-release.apk from app/release; it works on almost any phone from the last 8 years. app-armeabi-v7a-release.apk is for older 32-bit phones. For Google Play, choose Android App Bundle in step 4 instead.

    local.properties stays on the computer that builds the app. It isn't uploaded with the code, so the keys don't end up in a shared repository.

    One-time Firestore setup — The full set of Firestore rules for the app and this site: customers see only their own account, orders and chats; staff run the shop; only a Super Admin changes roles, keys and settings or clears data.
    1. Open the Firestore rules for this project.
    2. Click in the rules editor, select everything (Ctrl + A) and replace it with the rules shown here. They cover the whole app and admin site, so nothing else needs to stay.
    3. Press Publish, wait a few seconds, then press Reload at the top of this page.
    rules_version = '2';
// KustomoImprenta: who may read and change what. Paste into Firebase console → Firestore Database → Rules → Publish.
service cloud.firestore {
  match /databases/{database}/documents {

    // ── Helpers ───────────────────────────────────────────────────────────────
    function signedIn() { return request.auth != null; }
    function me() { return get(/databases/$(database)/documents/users/$(request.auth.uid)).data; }
    function active() { return me().get('status', 'Active') != 'Disabled'; }
    // A switched-off staff account loses access here too, not only on the website
    function isAdmin() { return signedIn() && me().get('role', 'user') in ['admin', 'super_admin'] && active(); }
    function isSuperAdmin() { return signedIn() && me().get('role', 'user') == 'super_admin' && active(); }
    // A customer the shop switched off can't place orders (no profile yet counts as not switched off)
    function mayOrder() {
      return !exists(/databases/$(database)/documents/users/$(request.auth.uid)) || active();
    }
    // A field left as it was (also true when it wasn't there before and still isn't)
    function unchanged(field) {
      return request.resource.data.get(field, null) == resource.data.get(field, null);
    }

    // ── Accounts ──────────────────────────────────────────────────────────────
    // Customers keep their own profile, but can't make themselves staff or switch themselves back on.
    // Staff manage customers; only a Super Admin changes roles or removes a profile (Clean Up).
    match /users/{uid} {
      allow read: if (signedIn() && request.auth.uid == uid) || isAdmin();
      allow create: if (signedIn() && request.auth.uid == uid
                        && request.resource.data.get('role', 'user') == 'user'
                        && request.resource.data.get('status', 'Active') != 'Disabled')
                    || isSuperAdmin();
      allow update: if (signedIn() && request.auth.uid == uid && unchanged('role') && unchanged('status'))
                    || (isAdmin() && unchanged('role'))
                    || isSuperAdmin();
      allow delete: if isSuperAdmin();

      // Saved designs and drawn shapes: the customer's own; staff can look; a Super Admin can clear them
      match /{sub}/{docId} {
        allow read: if sub in ['designs', 'shapes'] && ((signedIn() && request.auth.uid == uid) || isAdmin());
        allow write: if sub in ['designs', 'shapes'] && ((signedIn() && request.auth.uid == uid) || isSuperAdmin());
      }
    }

    // ── Orders ────────────────────────────────────────────────────────────────
    // A customer places orders in their own name and reads their own; staff handle everything after that.
    match /orders/{orderId} {
      allow read: if (signedIn() && resource.data.userId == request.auth.uid) || isAdmin();
      allow create: if (signedIn() && request.resource.data.userId == request.auth.uid && mayOrder()) || isAdmin();
      allow update, delete: if isAdmin();
    }

    // ── Order chats ───────────────────────────────────────────────────────────
    match /chats/{chatId} {
      function chatOwner() {
        return signedIn() && get(/databases/$(database)/documents/chats/$(chatId)).data.userId == request.auth.uid;
      }
      allow read: if (signedIn() && resource.data.userId == request.auth.uid) || isAdmin();
      allow create: if (signedIn() && request.resource.data.userId == request.auth.uid) || isAdmin();
      allow update: if (signedIn() && resource.data.userId == request.auth.uid && unchanged('userId')) || isAdmin();
      allow delete: if isAdmin();

      match /messages/{msgId} {
        allow read, create, update: if chatOwner() || isAdmin();
        allow delete: if isAdmin();
      }
    }

    // ── Employees (the shop's drivers): names and numbers, only for staff ──────
    match /employees/{id} {
      allow read, write: if isAdmin();
    }

    // ── Catalog ───────────────────────────────────────────────────────────────
    match /products/{productId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /categories/{id} {
      allow read: if signedIn();
      allow write: if isAdmin();
    }
    match /models/{id} {
      allow read: if signedIn();
      allow write: if isAdmin();
    }
    match /designPresets/{presetId} {
      allow read: if signedIn();
      allow write: if isAdmin();
    }
    // Designer Studio: shop-uploaded fonts, text layouts and the settings sets (Studio Settings page). Readable by
    // anyone so the app's designer has them before sign-in; only staff change them.
    match /designFonts/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /textLayouts/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /studioSettings/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // ── Shop Settings and App Keys ────────────────────────────────────────────
    match /appConfig/{doc} {
      allow read: if signedIn();
      allow write: if isSuperAdmin();
    }
    // The app's Home screen (Home Page on the admin site): any staff member may change it
    match /appConfig/home {
      allow write: if isAdmin();
    }

    // ── Payments ──────────────────────────────────────────────────────────────
    // The PayMongo secret key (Payments page): a Super Admin can save or replace it, nobody can read it back.
    // Only the payment server (FitFusionServer, with its service account) reads it.
    match /secrets/{doc} {
      allow read: if false;
      allow write: if isSuperAdmin();
    }
    // Payments in progress and the orders waiting for them: only the payment server uses these.
    match /paymongoSources/{id} {
      allow read, write: if false;
    }
  }
}
